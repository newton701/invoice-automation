# Data Dictionary

## Conventions
- Currency: INR only. Money is DECIMAL(14,2), HALF_UP rounding. Quantities are integers. Dates are ISO `YYYY-MM-DD`.
- IDs are immutable, zero-padded, and generated by one `IdFactory`. Seed: 20261022.
- Derived fields (marked **D**) are always computed from source rows, never generated independently.
- Tolerances (configurable): price +/-2%, tax 1.00 INR, header-vs-lines 0.01. Invoiced qty must not exceed received qty.
- Tax codes: TX00=0%, TX05=5%, TX12=12%, TX18=18%, TX28=28%.

## Supporting tables
**invoice_status_event** (append-only): `event_id` PK, `invoice_id` FK, `from_status` (null for first), `to_status`, `event_date`, `reason`. Transitions must follow the lifecycle graph. Rows are never updated.

**match_result** (bridge, N:M): `match_id` PK, `invoice_line_id` FK, `po_line_id` FK (null if no PO), `grn_line_id` FK (null if no receipt), `price_variance_pct`, `qty_variance`, `tax_variance`, `line_match_status`.

**exception_case**: `case_id` PK, `invoice_id` FK, `exception_type`, `routed_to` (OPERATIONS_ANALYST, APPROVER, PROCESS_OWNER, SYSTEM_ADMIN), `status` (OPEN, RESOLVED), `opened_date`.

## ground_truth (separate file, never read by rules)
`invoice_id` PK/FK, `issue_type` (CLEAN, PRICE_VARIANCE, QUANTITY_MISMATCH, DUPLICATE, MISSING_RECEIPT, TAX_VENDOR_ERROR), `edge_case_tags`, `duplicate_of_invoice_id` (null unless DUPLICATE), `expected_match_status`, `expected_payment_ready` (boolean).
